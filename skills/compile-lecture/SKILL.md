# Compile Lecture - 课程讲次编撰

你将通过阅读图片的方式，对用户提供的一讲课程的 PPT 图片进行吸收和理解。用户可能对该课程的 PPT 提出以下要求中的一种或几种：

1. 要求你整理成**知识点笔记**（为预习、学习和复习而设计的高等教育学习材料）；
2. 要求你撰写对应的**博客章节**（公开发表的内容，技术专业风格、教材式整理体）；
3. 要求你**解答**课程中的例题或作业（如有）；
4. 向你**询问和请教**课程中的具体内容。

你的转述要忠实于 PPT 等本地材料内容，一般不联网核实，但要对明显笔误保持警觉。

## 前置准备

如果用户**还没有**提供以下信息，你需要首先向用户提问：

### Q1：材料来源

需要分析的课件是哪一个？按材料形态分三条路径处理：

- **图片目录**（已导出课件每页图片）：可直接前往 Q2。
- **PPT 文件**（.pptx/.ppt）：你需要引导用户将 PPT 导出为每页图片（通过 Microsoft Office 的文件-另存为-JPEG 方式），才可继续分析。
- **PDF 文件**：运行自带的转换脚本 `<此SKILL目录>/scripts/pdf2img.py`：`python <此SKILL目录>/scripts/pdf2img.py <PDF路径>`。该脚本路径通常一定存在，一般无需二次探测。该脚本自洽：会自动安装 pymupdf 依赖到脚本旁的 `.deps/` 目录，不污染用户的环境；会输出 JPG 格式图片到课件目录旁的 `pages/` 子目录（或使用 `-o` 指定自定义输出目录），文件名按页码命名形如 `p001.jpg`。

### Q2：课件用途

如果用户没有提供具体指令，你需要明确用户需要你完成的内容。适合使用提问工具以多选题形式询问用户。

### Q3：存储位置

仅当 Q2 要求整理**博客文章**时，你才需要确认课程信息，方法如下。

你可粗略根据文件名和首张 PPT 来判断课程的基本信息，然后寻求用户确认以下细节：

- 准确的课程名
- 课程名的英文 slug
- 目标博客的存储位置、分类、标签

## 技能学习

完成了前置准备后，根据用户当前需求的不同，你可能需要学习和遵守一些额外的**规范文档**：

- 如果用户的需求包含整理知识点笔记，你*必须*完整阅读 [<此SKILL目录>/1-Writing-Knowledge-Notes.md](./1-Writing-Knowledge-Notes.md)。
- 如果用户的需求包含整理博客章节，你*必须*完整阅读 [2-Writing-Blog-Posts.md](./2-Writing-Blog-Posts.md)。

除了遵守上述规范外，还务必*注意*书写知识点笔记和博客章节的**文风**，这是文案质量的关键。
文风要像人类，不要像 AI。人类的文风是有逻辑的、有条理的、不碎片化的。

对于中文来说，最佳的参考文风是毛泽东同志写的文章，其遣词造句值得你参考和模仿。
当然，这篇技能文档及其附件文档的文风也值得你参考和模仿，尤其是对关联词和标点符号的使用。

## 阅读理解

完成了上述步骤后，相信你已对你所需要完成的任务有了充分的理解。下一步，你需要开始阅读 PPT 图片、分析 PPT 内容，过程中需*注意*下述事项：

- **阅读顺序**：按文件名自然排序确定页序。若文件名乱序，则页序需要靠内容推断，凭借推断结果工作。
- **唯一输入源原则**：所有原始图片必须*由你亲自阅读*，不得派遣子 agent 代读。因为图像内容的细节（重点标记、强调色、页间连贯性、笔迹与口吻）极易在子 agent 的转述中丢失上下文信息。你逐张阅读，可直接吸收页级结构化条目：知识点、术语、图表描述、公式（LaTeX）、存疑标记，以及应试信号——本页在讲课中的篇幅占比、是否含重点标记（"重点"、记号、★、下划线）、是否使用强调色高亮。
- **高难任务外派**：子 agent 的适用于两类任务——*核对和探索*（如术语一致性核对、存疑项复核、产出物交叉校对、深度思考或研讨），以及*解决较复杂的题目*（例如做数学例题、出新的例题、整理解题过程、分析长文本）并输出结果。分配子 agent 的核心目的是将长线思考内容进行外派委托，使得你更专注于眼前工作。

## 任务完成

阅读完了任务所需的 PPT（如果用户指定了具体范围，则有时并不需要读完）之后，你就可以开始完成用户指定的任务需求了。
中途遇到疑惑，建议使用提问工具向用户提问，而不是自行假设或越权处理。
